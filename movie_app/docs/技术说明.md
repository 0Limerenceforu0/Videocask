## 一、项目概览

- **定位**：跨端影视应用（Flutter）。片源来自**苹果CMS 采集站**，经解析后播放；支持缓存、磁力、AI 字幕、DLNA 投屏。
- **三端**：Windows（cmake+ninja）、Android（apk）、Web（build web + 本地代理）。
- **播放器内核**：桌面 `media_kit` / `mpv`；Web 走 `hls.js` + 同源代理。
- **目录约定**：
  - `lib/models` → `lib/services`（单例）→ `lib/providers`；`lib/data`、`lib/domain` 为早期空壳，逻辑已在 services/providers。
  - `lib/pages/detail/`：`detail_page.dart` 主文件只留字段与 `@override`，130 个方法按语义拆进 8 个 `part`（`detail_page_{player_ui,playback,episode,subtitle,download,data,dlna,misc}.dart`），每个是 `extension _DetailXxxExt on _DetailPageState`。

## 三、数据源与搜索

- 苹果CMS `ac=detail&wd=<关键词>&pg=N` 接口返回搜索结果；`m3u8` 通常是 master 列表，需再取 `2000k/hls/mixed.m3u8`（部分源要 http 而非 https）。
- **多源同名合并**：`ApiService.isSameMovieForMerge` + `seasonKeyOfName()` 做**季数感知**合并，避免把不同季归一（修复记录见 `api_service_search_merge_test.dart`）。
- **结果上限问题（已修复）**：搜索接口默认单页返回条数有限（常见 20 条），`searchMovies` 现读取响应 `pagecount` 做**翻页聚合**（单源上限 `_maxSearchPagesPerSource = 10` 页，约 200 条/源，`_mapInBatches` 并发度 3），按 `id` 去重；详情页推荐传 `maxPages: 1` 避免无谓翻页（见变更记录 2026-09-27）。
- 排查片源：`curl "源url?ac=detail&wd=<关键词>&pg=1"`。

## 四、播放链路

唯一入口：`detail_page._playEpisodeAsync` → `PlaybackUrlResolver.resolveForPlayback` → `playerService.play`（mpv）。

- 去广告代理：`openUrlForPlayer`（唯一调用点 `detail_page:3818`）→ `LocalMediaHttpServer.serveAdFreeHls`（桌面）/ Web 走同源代理。

## 五、HLS 去广告策略（核心）

> 主题：广告"还是没被过滤"的根因与"一劳永逸"方案。

### 5.1 根因：过滤器没坏，是"看天吃饭"

凡用 `#EXT-X-DISCONTINUITY` 分隔广告块的源都能拦；凡**整集等长切块无离群**或**单块无 DISCONTINUITY**的广告，与正片在 playlist 层长得一模一样，任何启发式都认不出。

实测采集站广告形态：

| 形态 | 特征 | 能否靠启发式拦 |
| --- | --- | --- |
| ① 跨域广告 CDN（旧） | 广告分片来自另一域名 | ✅ 按域名 |
| ② 同域片头/片尾贴片 | 与正片同域名、只在首尾、时长很短 | ✅ 首尾短块 + 离群 |
| ③ 同域中插广告（当前主流） | DISCONTINUITY 前后包夹的 5 片 / ~19.6s 短块，域名文件名与正片一致 | ✅ 中插全局离群 |
| ④ 等长切分（死区） | 整集被切成上百个等长短块（如 146 块 × 20s） | ❌ **无任何离群块** |
| ⑤ 单块无 DISCONTINUITY（死区） | 广告与正片混在同一块 | ❌ 启发式无信号 |
| ⑥ 已知广告路径注入 | 分片 URL 含 `adjump` / `preroll` 等广告目录名 | ✅ **按路径段**（最可靠，见 5.2） |

形态 ⑥ 是 CDN 侧注入的典型形态：播放列表在到达播放器前就被改好，广告与正片**同域名、同协议、同文件类型**，
只有 URL 路径不同（实测风暴 CDN 在正片第 99 片后插 9 片 `/video/adjump/time/*.ts`、26.04s，前后各一条 DISCONTINUITY）。
此时网页广告过滤扩展（uBlock / AdGuard）结构性无效——不理解 m3u8 内容就无法区分，只能在播放列表层清洗。

### 5.2 "一劳永逸"方案：路径特征 + 用户规则清单 + 安全启发式

**三套防御，四层判定**（Dart 与 Web 同源同规则）：

- **pass0 规则清单**（`assets/ad_block_rules.json` + 内置路径特征）：命中任一判据的分片**一律判广告**，优先级最高。
  - **内置路径特征**（默认启用，`AdBlockRules.builtinPathSegments`）：URL **路径段精确匹配**
    `adjump` / `advert` / `preroll` / `postroll` / `midroll` / `adtime` … 共 16 个。
    这是形态 ⑥ 最可靠的判据——不依赖时长与块结构，「块数多导致中位数失效」「广告超 60s」等启发式死区它照样拦得住。
    用**路径段**而非子串，是为了避免 `downloads/` 命中 `ads/` 这类误伤（切出来的段是 `downloads` ≠ `ads`）。
  - 用户 `blockedHosts`（域名子串）/ `blockedUrlSubstrings`（URL 子串）/ `blockedPathSegments`（追加路径段）：
    形态 ④⑤ 死区的**永久解法**——把已知广告特征写进 JSON，一次配好永久生效，无需改代码。
- **pass1 跨域块 + 首尾短块**：块内域名全异于正片基准域名 → 广告；首尾块短且是时长离群块 → 广告。
- **pass2 中插短块**（两条判据取或）：
  - **全局离群**：块时长 ≤ 典型块中位数的 1/5，且左右相邻正片块都 ≥ 120s 且 ≥ 其 6 倍；
  - **局部对比**：广告块 < 左右邻居 × 0.6 即可，**不要求全局离群**，用于补「块时长中位数不够大」的盲区。
    仅当**两道闸门同时满足**才启用：非空块数 ≤ 8（DISCONTINUITY 是注入标记而非等长切分）且两侧正片均 ≥ 120s
    （短视频里的短分段多为场景切换，不是广告）。

### 5.3 关键安全约束（不可删）

1. 仅处理 VOD（含 `#EXT-X-ENDLIST`）；master 列表 / 直播不动。
2. **「离群」必须用块时长中位数判**（`HlsAdFilter.adOutlierDominance`，factor 5），不能用最长块——否则等长切分会被误删正片（事故见 `验证与用例清单.md` 第四节）。
3. 正片基准域名以**最长块**时长为准（时长加权），不能用全局聚合（多段广告时长加起来可能超过正片）。
4. **占比过半的块免疫所有规则**；剔除总量 > 50% 时整体放弃过滤（兜底不删光）。
5. 加密流（`#EXT-X-KEY` / `MAP` / `BYTERANGE`）Web 端直接跳过过滤（宁可放过）；桌面端走全量本地代理，剔除后分片序号位移必须保留**原始序号**供 AES-128 隐式 IV。

### 5.4 双端实现与一致性

| 端 | 过滤实现 | 规则来源 |
| --- | --- | --- |
| 桌面（Dart） | `lib/services/hls_ad_filter.dart`（`HlsAdFilter.filterContent` 纯函数）+ `m3u8_playlist_resolver.dart`（懒加载 `assets/ad_block_rules.json`） | `rootBundle.loadString('assets/ad_block_rules.json')` |
| Web（Python） | `tool/web_dev_server.py::filter_m3u8_ads` + `_segment_blocked` | 同 JSON 文件，函数内 `_load_ad_rules()` 缓存 |

两者阈值常量完全一致（45s 首尾 / 60s 中插 / 中位数 factor 5 / 邻居 120s 或 6× / 局部对比 0.6 且限 ≤8 块 / 50% 上限），
内置路径特征清单也逐字对齐（Dart `builtinPathSegments` ↔ Python `BUILTIN_AD_PATH_SEGMENTS`）。
**改任一端都必须同步另一端**，否则同一片源在桌面端和 Web 端表现不一致。
验证：Dart `verify_filter.dart` 8/8、Web `verify_web_filter.py` 7/7、真实 146 块样本零误删。

### 5.5 诊断工具：换源 / 遇新广告形态时先跑它

```bash
dart tool/hls_ad_diagnose.dart --fixtures              # 诊断 test/fixtures/hls 全部样本
dart tool/hls_ad_diagnose.dart <m3u8文件>...           # 诊断指定文件
dart tool/hls_ad_diagnose.dart --url <m3u8地址>        # 直接抓线上（带 UA/Referer）
```

输出块结构（按 DISCONTINUITY 切分）、哪些块被判广告、剔除片数/秒数，并做两项检查：
**已知广告特征残留**（命中 `adjump` 等却没被删 = 漏判）与**疑似正片误删**（被删分片是纯数字顺序命名）。

启发式是概率手段，没有真实样本验证的改动一律不该进主干。新样本固化方式见 `验证与用例清单.md`。

### 5.6 用户怎么用

编辑 `assets/ad_block_rules.json`：

```json
{
  "blockedHosts": ["ad-cdn.example.com"],
  "blockedUrlSubstrings": ["/adzone/", "_ad_"],
  "blockedPathSegments": ["myad"],
  "localContrastRatio": 0.6,
  "maxAdBlockSeconds": 60,
  "disableBuiltinPathSegments": false
}
```

内置路径特征（adjump / preroll / postroll / midroll / advert …）**默认已启用，无需手工填写**。
`blockedPathSegments` 用于**追加**你自己发现的特征；`maxAdBlockSeconds` 调大可拦更长的贴片（如 90s），
代价是正片分段被误删的风险上升；怀疑误删时把 `disableBuiltinPathSegments` 设为 `true` 即可验证是否由内置特征引起。

保存即生效（无需重新打包逻辑层；Web 端重启 `web_dev_server.py` 或清 `_AD_RULES_CACHE`）。
⚠️ 误填正片域名会导致整段被删，但 50% 上限兜底不会删光——填前先确认是广告域名。
