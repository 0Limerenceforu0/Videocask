# 验证方式与用例清单

> 本文回答三个问题：**为什么改动主要靠用例验证**、**还有哪些验证方式**、
> **全部用例都在哪**。最后附 HLS 去广告的「真实片源样本库」。
>
> 统计口径：`test/` 下 61 个 `*_test.dart`，共 **454 条用例**（其中 1 条被跳过）。

> ⚠️ 2026-10-22 更新：本文第三节的分组条数是 2026-10-20 的快照，尚未逐组刷新；

## 一、为什么主要靠用例

不是偏好，是环境限制下的唯一可行解：

| 限制 | 具体表现 |
| --- | --- |
| **单测里发不出网络请求** | `DioFactory` 的缓存拦截器依赖 `getTemporaryDirectory()`，测试环境没有 path_provider 实现 → 任何真实网络请求一律报"网络请求失败"。 |
| **单测里跑不了真实播放器** | media_kit / mpv 需要原生窗口与解码器，`flutter test` 的 headless 环境起不来。 |
| **采集站数据天天变** | 今天抓到的 m3u8 明天可能换域名、换广告时长、甚至换注入方式。靠"我刚跑了一遍没问题"没有保质期。 |
| **三端 × 多源 × 多集** | Android / Windows / Web × 3 个采集站 × 几百集，人工覆盖不了。 |

用例提供的正好是这几条的补集：**纯函数、可重复、秒级、能把"不该删"的反例钉死**。
所以本项目的做法是——把判定逻辑抽成 public 纯函数（如 `HlsAdFilter.filterContent`、
`ApiService.isSameMovieForMerge`），再用用例覆盖。

### 它的局限（必须承认）

用例只能证明"我构造的输入 → 我断言的输出"。**构造不出真实形态时，用例全绿也可能是假的。**
下面第四节记录的误删事故就是活例子。

## 二、还有哪些验证方式（都可用，且本次组合使用过）

| 方式 | 能证明 | 不能证明 | 成本 | 什么时候用 |
| --- | --- | --- | --- | --- |
| **① 真实抓包一次性验证** | 当前线上真实数据下确实生效 | 抓完即弃，下次改代码不复验 | 低（几分钟） | 定位阶段，确认"是不是真的、形态是什么" |
| **② 真实样本 fixture 回放**（推荐） | 真实数据 + 可重复 + 防回归 | 样本会过期，需定期刷新 | 低 | **固化结论，长期防回归** |
| **③ CDP 实机浏览器验证**<br>`tool/cdp_*.js` | 页面能加载、能起播、不灰屏 | 无法断言"广告被剔除了"，只能看现象 | 中（需起测试实例、必须 `--mute-audio`） | UI / 播放链路的端到端 |
| **④ 手动跑包人眼确认** | 最真实的最终体验 | 不可回归、不可举证 | 高（要打包、要装、要看完一集） | 发布前最终确认 |
| **⑤ 产物字符串探测** | 新代码确实编进了 `app.so` / `main.dart.js` | 逻辑对不对完全不知道 | 极低 | 交付前冒烟 |
| **⑥ 静态分析 + 全量测试** | 没引入语法/风格/回归问题 | 逻辑正确性 | 低 | 每次改动必跑 |

> ⑤ 的关键坑：AOT 产物 `app.so` 里中文字符串是 **UTF-16LE**，
> 用 `w.encode('utf-8')` 探测会全部误判 MISS，必须
> `w.encode('utf-16-le') in data`。

本次的组合是：**① 抓真实 m3u8 定位形态 → ② 固化成 fixture 写成用例 → ⑥ 全量回归 → ⑤ 产物冒烟 → 三端打包**。

## 四、HLS 广告形态样本库（`test/fixtures/hls/`）

合成用例覆盖不到的真实形态，全部抓包固化在这里，由
`test/services/hls_ad_filter_real_sample_test.dart` 每次跑测试时回放。

| 样本文件 | 来源 | 结构 | 期望 |
| --- | --- | --- | --- |
| `real_ffzy_play9_midroll_ad.m3u8` | 非凡 play9 | 280 片 / 3 块：正片 89 片 356.6s → **5 片 19.63s** → 正片 186 片 744.9s | 剔除 5 片 |
| `real_feifeikan_midroll_ad.m3u8` | 飞飞 kan | 275 片 / 3 块：同形态中插广告 | 剔除 5 片 |
| `real_ffzy_plays_146blocks_no_ad.m3u8` | 非凡 plays | **896 片 / 146 块**，整集被 DISCONTINUITY 切成大量约 20s 的等长短块 | **一片不删** |

### 已发现的形态

1. **跨域广告 CDN**（旧）：广告分片来自另一个域名 → 按域名判定。
2. **同域片头/片尾贴片**：与正片同域名同命名，只在首尾、时长很短。
3. **同域中插广告**（当前主流）：正片中段被 DISCONTINUITY 前后包夹的
   5 片 / 约 19.6s 短块，域名和文件名风格与正片完全一致
   （都是 32 位 hex 的 `.ts`），**只有"时长异常短 + 两侧都是正片"一个可判据**。
4. **等长切分陷阱**（不是广告）：某些源把整集切成上百个等长短块。

### 事故记录：等长切分被误删（2026-09-27）

规则 2 原先拿"最长的块"当基准，判定首尾块是否"短得离谱"。
在 `real_ffzy_plays_146blocks_no_ad.m3u8` 上：最长块 120.8s，首块 20.17s，
120.8 ≥ 20.17 × 5 → 首块+末块被当成片头/片尾贴片删掉，**误删 8 片 / 30.37s 正片**。

修复：改用**块时长中位数**判离群（`HlsAdFilter.adOutlierDominance`）。
等长切分里没有离群块，一片不删；含广告的样本仍准确剔除 5 片。

> 这条正是"合成用例全绿 ≠ 真实数据没问题"的实证：**19 条合成用例一条都没拦住它，
> 是真实样本回放第一次跑就抓出来的。**

### 刷新样本

采集站改版导致样本过期时：

```bash
python tool/capture_hls_samples.py 凡人修仙传 --titles 3 --episodes 2   # 先看结构
python tool/capture_hls_samples.py 凡人修仙传 --titles 3 --episodes 2 --write  # 落盘
flutter test test/services/hls_ad_filter_real_sample_test.dart
```

脚本会打印每份样本的块结构（片数 / 时长），人工判断哪些是广告样本、
哪些应作为"不许删"的反例，再按内容重命名并写进用例断言。

## 五、新增验证的操作步骤

1. **先抓真实数据**：`python tool/capture_hls_samples.py <关键词>`（或 curl 相应接口）。
2. **判断形态**：看块结构，确认哪块是广告、有没有"等长切分"这类陷阱。
3. **写合成用例**：把形态抽象成最小列表，写进对应的 `*_test.dart`。
4. **固化真实样本**：`--write` 落盘到 `test/fixtures/`，在 `*_real_sample_test.dart`
   里加断言（**含广告的样本和"不许删"的反例要成对出现**）。
5. **全量回归**：`flutter test` + `flutter analyze`。
6. **产物冒烟**：`app.so` 用 UTF-16LE 探测新文案是否编进包。
