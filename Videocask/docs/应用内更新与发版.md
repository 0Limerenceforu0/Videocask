# 应用内更新与 GitHub 发版

> 一句话：三端产物传到 **GitHub Releases**，客户端读 `releases/latest` 比对版本，
> 有新版本就下载并就地安装。历史版本天然留档，随时可按 tag 下载。

---

## 一、整体链路

```
┌────────── 发版侧（本机，一次性） ──────────┐
│ bump_version.dart                        │
│   → pubspec version x.y.z+N              │
│   → constants.appVersion x.y.z           │
│ 三端构建 + package_deliverables.py        │
│   → deliverables/罐子_*_v{x.y.z}.*        │
│ publish_release.py                       │
│   → GitHub Release(tag v{x.y.z})          │
│   → Assets: videocask-*-v{x.y.z}.*           │
└──────────────────────────────────────────┘
                    ↓
┌────────── 客户端（运行时） ──────────┐
│ 启动 5s 静默检查 / 设置页手动检查        │
│   GET api.github.com/.../releases/latest │
│   比对 AppConstants.appVersion           │
│ 有新版本 → 弹窗（版本/说明/体积）          │
│ 下载 → 直连优先，失败切镜像              │
│ 安装 → Android 系统安装器 / Windows 自替换 │
└──────────────────────────────────────┘
```

---

## 二、首次配置（只做一次）

### 1. 生成 GitHub Token

GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens**
→ Generate new token：

- **Repository access**：只选 `Videocask`
- **Permissions**：`Contents` = **Read and write**（发布 Release 只需要这一项）

### 2. 写到本地 `.env`

在 Flutter 项目根目录（`movie_app/`）新建 `.env`：

```
GITHUB_TOKEN=github_pat_xxxxxxxx
```

`.env` 已在 `.gitignore` 里，不会被提交。模板见 `.env.example`。

> 客户端**不需要**任何 Token：仓库是 public，读 Release 是匿名只读接口。

## 三、发一次版

### 1. 升版本号

```bash
dart run tool/bump_version.dart
# 1.1.7+67 → 1.1.8+68，同时改 lib/config/constants.dart 的 appVersion
```

规则（用户 2026-10-22 定）：**只有「Android + Windows + Web 三端一次性打包交付」时才升版本号**。
默认升 patch 位；要升 minor 用 `--minor`。

### 2. 补人工说明

- `lib/config/changelog.dart`：应用内「更新日志」展示的条目
- `CHANGELOG.md`：发版脚本会把对应版本段落用作 **Release 说明**
- `README`（若涉及）

### 3. 三端构建 + 打包

```bash
flutter build apk --split-per-abi
flutter build windows
flutter build web
python tool/package_deliverables.py
```

产物落在 `deliverables/`，例如：

```
罐子_android_arm64_v1.1.8.apk
罐子_android_armeabi-v7a_v1.1.8.apk
罐子_android_x86_64_v1.1.8.apk
罐子_windows_v1.1.8.zip
罐子_web_v1.1.8.zip
```

### 4. 提交并推送代码（重要）

Release 的 tag 指向的是**已推送的提交**。先：

```bash
git add -A && git commit -m "1.1.8: ..."
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY git push origin main
```

> 本机默认带 `http_proxy=127.0.0.1:1978`，对 GitHub 的 CONNECT 会返回 502，
> push 必须清代理直连（`git ls-remote` 走代理能过，不能当连通性证据）。

### 5. 发布到 GitHub Releases

```bash
# 先演练：只打印会传什么，不联网
python tool/publish_release.py --dry-run

# 正式发布
python tool/publish_release.py
```

脚本会自动：

1. 校验 `pubspec.version` 与 `constants.appVersion` **必须一致**（不一致直接退出）；
2. 只挑文件名里带本版本号的产物，不会把历史版本一起传；
3. 把中文名重命名为 ASCII（避免下载器/代理乱码）；
4. 用 `CHANGELOG.md` 对应段落生成 Release 说明；
5. 建 tag `v{x.y.z}` + Release，逐个上传 Assets；
6. 打印 Release 链接。

常用参数：

| 参数 | 用途 |
|---|---|
| `--dry-run` | 只演练不联网 |
| `--update` | 版本已存在时更新说明、补传/替换资产（幂等） |
| `--prerelease` | 标为预发布（客户端仍会读到，只是 GitHub 上显示 Pre-release） |
| `--mandatory` | 说明前加 `[强制更新]`，客户端跳过「稍后」 |
| `--repo owner/name` | 换仓库 |

## 四、资产命名约定

上传名固定为：

```
videocask-android-arm64-v{ver}.apk
videocask-android-armeabi-v7a-v{ver}.apk
videocask-android-x86_64-v{ver}.apk
videocask-windows-x64-v{ver}.zip
videocask-web-v{ver}.zip
```

客户端只按**关键词**匹配，大小写不敏感：

- Android：名字必须含 `android`，再按设备 ABI（`Build.SUPPORTED_ABIS`）精确匹配；
  没有对应 ABI 时依次回退 `arm64-v8a → armeabi-v7a → x86_64 → 不带 ABI 的通用包`。
- Windows：含 `windows` 且以 `.zip` 结尾。
- Web：含 `web` 且以 `.zip` 结尾（Web 不自动安装，只提示刷新）。

历史的中文命名（`罐子_android_arm64_v1.1.7.apk`）同样能被识别，所以老版本不用重传。

## 五、客户端行为

| 平台 | 检查 | 下载 | 安装 |
|---|---|---|---|
| Android | 启动 5s 后静默 + 设置页手动 | 直连 → `ghproxy.net` → `gh-proxy.com` 依次回退 | 下载到应用私有 cache，经 FileProvider 调系统安装器 |
| Windows | 同上 | 同上 | 解压到临时目录，生成批处理，应用退出后 robocopy 覆盖并重启 |
| Web | 不检查（刷新即最新） | — | — |

### Android 的「安装未知应用」

Android 8.0+ 系统强制要求用户在设置里单独授权，代码无法绕过。流程：

1. 点「下载并更新」→ 下载完成；
2. 若未授权，弹窗提示「需要『安装未知应用』权限」，给「去授权」按钮；
3. 跳到系统的本应用授权页，打开开关返回；
4. 点「重试」→ 弹系统安装界面。

### Windows 的自替换

绿色版没有安装器，正在运行的 `movie_app.exe` 无法被覆盖，因此：

1. 下载 zip → 解压到 `%TEMP%\videocask_update_payload`；
2. 生成 `%TEMP%\videocask_apply_update.bat`，内容为「等进程退出（最多 60s）→ robocopy 覆盖 → 启动新 exe → 自删」；
3. 应用主动 `exit(0)`；
4. 批处理接管，替换完成后重启新版本。

**正在播放的视频会中断**，弹窗里会提示。更新失败时批处理会停下并 `pause`，
同时在 `%TEMP%` 留下 `update_error.log`。

### 静默检查的克制

- 启动后延迟 5s，避开首屏加载；
- 结果缓存 1 小时（GitHub 匿名 API 限流 60 次/小时/IP）；
- 用户点过「稍后」后，**同一构建号不再弹**（除非 Release 标了 `[强制更新]`）；
- 所有失败路径都只写诊断日志，绝不打扰用户。

## 六、需要知道的坑

1. **GitHub API 限流**：未认证 60 次/小时/IP。共享出口 IP（公司/校园网）可能提前耗尽。
   客户端已做 1 小时缓存；若手动检查报 403，等一会儿再试。
2. **`api.github.com` 在部分网络下不可达**：检查更新会失败，但**不影响应用其它功能**。
   大文件下载有镜像回退；API 本身没有可靠公共镜像，必要时给系统挂代理。
3. **`deliverables/` 不能进 git**：当前已 361MB，提交会让仓库历史永久膨胀。
   所有发行包只走 Release Assets。
4. **构建前别跑 `flutter test`**：它会重写 `GeneratedPluginRegistrant.java` 并引入
   `integration_test`，导致 `build apk --no-pub` 编译失败。已踩过，先删该文件再构建。
5. **版本号三处必须一致**：`pubspec.version`、`constants.appVersion`、tag。
   前两个由脚本校验，tag 由脚本生成，不会漂移。
6. **`--dart-define=APP_BUILD_NUMBER=N`** 可选：不传时客户端只按三段版本号比较。
   项目规则保证每次交付 patch 递增，因此不传也能正确判断新旧。
